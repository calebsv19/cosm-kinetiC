# Opt-in native field packet transport

This is a trusted-local PhysicsSim Main Edit development route for open-atmosphere
workers. It changes scientific I/O and retained storage, with existing solver and
physical acceptance owners unchanged. It is not a public untrusted upload API.

Select `io_format="field_packet/v1"` in `open_atmosphere.run`,
`coupling.fluid_adapter.run`, or `coupling.fluid_packets.run`. Their default is
legacy JSON. The native CLI is `worker --field-packet REQUEST.fpk`; stdout is a
field packet. Do not decode stdout as text. Native ownership checks, bounded
capture, terminal process verification and whole-file SHA256 receipts still apply.
Attempts retain input.fpk, request.fpk, fields.fpk and accepted.fpk in this mode,
plus captured stdout/stderr and compact receipts. Successful copied staging may
retire only after accepted checkpoint publication and active-consumer checks.

For a new durable replay, use both explicit keywords:

```python
from coupling.journal import FIELD_PACKET
from coupling.transport_replay import ReplayRun
run = ReplayRun(fresh_root, config, pulse, packet_steps=10,
                io_format="field_packet/v1", journal_mode=FIELD_PACKET)
run.initialize()
run.advance(0, 10)
# Reopen with the same config, pulse and explicit keyword values.
run.audit()
```

The replay binding pins native I/O mode, journal codec, source and worker bytes.
Changing mode or implementation refuses reopening; this is not an implicit
migration of historical journals. Native wire format is not part of physical
state identity, so the same worker can continue an accepted state across JSON
and packet calls. Worker identity checks remain enforced.

## Wire shape and limits

The24-byte header is `PSFPK01\n` followed by little-endian uint64 manifest length
and payload length. The UTF-8 JSON manifest contains exactly schema, value and
arrays. Schema is `physics_sim_field_packet/v1`. Homogeneous arrays of at least256
float64 or signed int64 values are represented by
`{"$field_packet_array_v1": index}`; each contiguous payload record carries dtype,
count, offset and CRC32. Values are little endian. Mixed/small lists stay JSON.
Types, signed zero, subnormals and exact int64 values survive codec roundtrip.
Scientific adapters retain their own admissible-number restrictions.

Bounds:256MiB complete packet,1MiB manifest,1,024 chunks,8,388,608 values per
chunk,32 levels of nesting,512MiB logical referenced array bytes. Count every
reference against the logical bound, including shared array occurrences. Python
encoding deduplicates identical dtype/bytes; native output deduplicates shared
JSON-C array pointers. Decoders reconstruct independent mutable lists/arrays.
Truncation, trailing bytes, wrong magic/type/count/offset/reference, uncovered or
unused chunks, nonfinite arrays and CRC mismatches refuse. Python also rejects
duplicate manifest keys. The trusted-local native JSON-C parser is not advertised
as rejecting duplicate object keys.

CRC32 detects accidental corruption; existing lifecycle SHA256 and source/worker
pins carry provenance. Neither is a public authorization system. The format is
app-private; current core_pack is a path/seek-based offline container and lacks
the nonseekable stdout/BLOB route used here without extra file copies or a shared
streaming API. Existing pack/VF3D owners and shared versions are unchanged.

The new journal mode zlib-compresses the packet directly, keeps a1GiB journal
allocation cap, a256MiB decompressed packet cap and the packet logical bounds.
Legacy journal formats and their256MiB decoded scientific-JSON cap are unchanged.
The old byte shuffle can compress smaller; new mode is an explicit alternative.
This route removes decimal field strings and full scientific JSON expansion in
the new journal owner. It does not remove native JSON-C nodes, Python lists or
all in-memory copies, and does not admit128³simulation by itself.
