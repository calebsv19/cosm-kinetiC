# Factor reference numerical-command supervision

The remaining 139 factor-building reference wrappers now run their numerical
command through the anchored CFD supervisor frozen into their source packet.
Together with the earlier 55 plain wrappers, all 194 identified legacy polling
loops in this reference family are migrated. This count covers the identified
family/pattern; it is not a repository-wide process/writer completion claim.

The factor-family registry is config/reference_factor_supervision_families.json.
Its stage explicitly says numerical command supervision only, and factor compiler
hardening remains false. Every solver and factor compiler command expression,
command environment, RSS cap and wall cap was compared with the pre-edit source
AST and remains unchanged. Exact baseline/final source and the comparison report
are retained. Adding supervisor bytes to SOURCES creates a new immutable source
identity; no historical factor/run record was rewritten.

New numerical receipts are create-only and carry limited command/anchor terminal
scope with complete descendant termination false. Existing admission checks are
explicit under python -O. Public run names are checked before allocation. Cached
acceptance also requires no saved diagnostic failure. Resource caps and uncertain
supervision holds have distinct failure kinds. Existing numerical gate logic,
combined chronological logs and factor build/readback metadata remain in each
wrapper. No physical acceptance gate or numerical campaign was executed.

The actual control-only Make suite passed six test methods: two factor-family
methods plus four imported plain-family control methods. Factor methods execute
278 fresh synthetic success/nonzero cases and cached readbacks across all 139
families, and reject invalid names before factor build/allocation. Factor build
calls return clearly labeled synthetic library bytes/compiler/SDK metadata;
only the numerical child supervision runs actual processes. These fixtures
verify control flow, hashing, receipt/cache preservation and combined logs, not
native factor ABI or Accelerate qualification. The plain-family four-method
Make regression passed separately after this migration.

Direct factor compiler/SDK identity calls and factor-record publication are still
the old implementation. They require bounded staged compiler execution,
create-only build-record publication, failed-attempt retention, exact reuse and
recovery qualification. Strict legacy root/JSON admission, complete descendant
ownership, aggregate/hard quotas and archive-backed retirement remain open.
Canonical still requires separately reviewed adoption. No commit, installation,
release, backup transfer or pruning occurred. This packet is outside the frozen
later prepared backup.
