PhysicsSim has tested lifecycle repairs in Main Edit, but the canonical checkout
has not adopted them. The highest operational risk remains broad recursive
cleanup in canonical `make/rules-runtime.mk:27` and package/release recipes.
Do not consider Main Edit tests protection for commands run in canonical.

## Recommended order

1. Adopt the reviewed cleanup guard into canonical after reconciling its exact
   files and preserving unrelated CFD work. Build, Water and scene-cache proofs
   must pass against the adopted tree. Until then, avoid ordinary canonical clean.
2. Complete a supported-command writer inventory, including native C, shell,
   Python, fixture and package consumers. For each output declare root, owner,
   class, replacement, interruption and retention policy. Complete path admission
   and exact expected artifact inventories before treating cached runs as complete.
3. Separate `clean` from explicit evidence retirement, environment retirement and
   package retirement. `clean-plan` should be the default preview; `clean` may
   remove only exact owned disposable outputs. Implement owner-terminal checks,
   verified independent archive coverage and checksum readback before pruning.
4. Finish interruption recovery: native job lifetime/log limits, coherent multi-file
   metadata recovery, failed compiler-prefix recovery and escaped-descendant holds.
   Add aggregate storage/workflow budgets; sampled log/RSS caps are not hard quotas.
5. Complete build provenance through headers, libraries, toolchain and configuration.
   Cached factor receipts bind preserved bytes, but do not requalify a changed
   current compiler/SDK or the real CFD factor ABI.
6. Consolidate one operator guide: status/doctor, isolated build, supported first
   proofs, cleanup preview/apply, archive/restore and explicit retirement. Reduce
   chronology in the current overview after adoption. Qualify real signing,
   installed packages and downstream consumers separately.
