## Objective

Finish a bounded PhysicsSim operating cleanup that prevents routine clean from
deleting retained evidence, preserves the repair work independently, fixes the
two reproduced launcher configuration defects, and makes ordinary operation
clear and repeatable. Review and adopt the existing packaging repairs without
expanding into a comprehensive security or cross-program audit.

## Completion requirements, in priority order

1. **Adopt the essential guarded cleanup foundation.** Recheck canonical and
   Main Edit ownership and dirty state. Inventory the exact files and dependencies
   needed for build-output ownership, retained-evidence separation, and guarded
   clean. Preserve existing work and prepare a narrow reviewed patch; never copy
   the whole dirty Main Edit tree. Within authorized integration boundaries,
   apply that patch to the intended source checkout. Demonstrate build, cleanup,
   and rebuild in disposable roots, with retained-evidence sentinel hashes
   unchanged and unsafe targets refused. Pass the supported headless build,
   Water smoke and scene-project cache-output proof. Record exactly which
   checkout now has the protection. A staged patch alone is not completion of
   canonical adoption. Never use the old broad clean on valuable live roots.

2. **Complete independent preservation.** Reconcile the previously prepared
   archive bundle with newer repair evidence. Produce an exact payload manifest,
   hashes, coverage and destination. Use the existing supported archive route
   subject to its authorization requirements; the prior rejected upload must
   not be retried through another route. Transfer only when permitted and
   independently retrieve and verify the stored payload. Report any pending
   authorization as an open requirement, not a completed backup. Preserve the
   earlier verified CFD archive and all local originals.

3. **Repair the two reproduced launcher configuration defects.** macOS must
   use writable runtime configuration without allowing saves to mutate packaged
   resources; handle existing links without deleting user state. Linux must
   publish a complete staged configuration and refuse or safely reconcile an
   interrupted partial copy. Verify package-resource hashes, interrupted-copy
   behavior, reruns and existing configuration preservation using disposable
   fixtures. Retain read-only inspection behavior and run affected regressions.

4. **Publish one concise operating contract.** Align Make help and the relevant
   agent/operating documentation with the final behavior: disposable and retained
   roots, clean inspection/application, supported first proofs, interrupted setup
   recovery, and archive location/coverage. Keep the longer audit as history;
   remove ambiguity about which checkout and commands are protected.

5. **Review and integrate the existing packaging repairs.** Bound the macOS
   bundler and Linux desktop installer diffs and their dependencies. Resolve
   demonstrated defects and review findings needed for those repairs, then run
   focused regressions and feasible platform validation. Identify unavailable
   platform checks explicitly. Record source integration separately from real
   packaging, installation, GUI acceptance or release. An unavailable required
   check remains open rather than silently passing.

## Overnight execution boundaries

- Resume only through the user's/app's goal controls. This document does not
  activate a paused goal or schedule an unattended job.
- Work in bounded slices with exact changed-file inventories, preserved inputs,
  meaningful targeted checks and durable receipts at each stopping point.
- Inspect ownership before consequential edits. Preserve concurrent and
  pre-existing work; never bulk-copy, reset or discard the dirty Main Edit tree.
- Use disposable fixtures for destructive and failure-injection tests. No broad
  cleanup, retained-evidence retirement, archive pruning or user-data deletion.
- No commits unless specifically requested. No version changes, installed-app
  refresh, signing, release, publication, Registry mutation, fleet operations or
  new automation under this plan. Archive transport alone follows its existing
  supported route and exact authorization requirements.
- Bound individual test/build processes and resource use. On repeated failure,
  unexpected ownership drift or resource pressure, preserve evidence and stop
  the affected slice; continue only independent authorized work. Do not expand
  the project to explain an unrelated failure.
- Do not start new audit families, CFD algorithm work, broad numeric hardening,
  comprehensive hostile-writer defenses, quota frameworks or cross-program
  standardization. A new finding enters a deferred list unless it directly
  blocks a completion requirement or threatens current evidence.
- Do not repeat passing checks without a relevant change or unresolved concern.
  Report source-tested, platform-tested, integrated, archived and human-accepted
  states separately.

## Finish line and final handoff

Stop when the five requirements have evidence and the affected regressions pass.
Deliver the exact adopted/staged file list, checkout identities, clean safety
proof, archive retrieval receipt, launcher/packaging validation, operating guide,
and a short deferred-risk list. If authorization, integration boundaries or a
required platform check prevent completion, identify that item precisely and
complete the other independent work; do not claim the goal achieved. The old
audit's exhaustive checklist is not a prerequisite for this focused finish line.
